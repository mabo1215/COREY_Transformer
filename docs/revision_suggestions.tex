\section*{Editorial Summary and Recommendation}

\noindent\textbf{Manuscript type:} Regular paper.\\
\textbf{Target venue:} IEEE Transactions on Parallel and Distributed Systems
(TPDS).\\
\textbf{Overall recommendation:} \textcolor{blue}{\textbf{Major Revision}}
(scope is a good fit; acceptance hinges on rigor, positioning, and
generality).

\medskip
\noindent The manuscript studies runtime scheduling of memory-bound
selective-scan kernels for Mamba state space models on GPUs, and reports a
careful, honest \emph{negative} result: an entropy-guided runtime scheduler
preserves outputs exactly but cannot beat a well-tuned static chunk size
because the online statistic cost is irreducible. This is squarely within
TPDS scope (parallel/GPU kernel scheduling, runtime adaptivity, performance
characterization of accelerator workloads), and a rigorous negative result
with a clean decision-quality/decision-cost decomposition is a legitimate and
useful TPDS contribution. The reservations are not about fit but about (i)
experimental rigor and measurement parity, (ii) positioning against the
parallel/distributed scheduling and autotuning literature, and (iii) the
generality of the conclusion beyond a single architecture and prompt regime.

\noindent\textbf{Decision logic.} The contribution is publishable at TPDS if
the authors (a) close the measurement-parity and formula-consistency gaps so
the negative result is unimpeachable, (b) position the work against

sharply scope the claim to the regime actually measured.

\section{Major Issues}

\subsection*{M1 \sev{Major} Measurement parity and the strength of the
negative claim}
The headline conclusion (``best static chunk beats every adaptive variant'')
is only as strong as the fairness of the timing methodology. A prior automated
review flagged a warmup-parity asymmetry (COREY paths measured with warmup
vs.\ static/off paths measured cold, including JIT compilation). For a
\emph{negative} result this is the central threat to validity: any
unfavorable bias against the adaptive path inflates the conclusion.
\action{Audit every latency table so that all compared policies share
identical warmup, repeat counts, synchronization fences, and JIT state.
Re-run or explicitly annotate any row that does not. State the protocol once,
centrally, and reference it from each table.}

\subsection*{M2 \sev{Major} Formula-vs-implementation consistency}
Equation~(2) (chunk rule) and the appendix tile-mapping formula must match the
code exactly. Reported issues: a floor-vs-round discrepancy (floor yields 256,
round yields 512 for $r{=}0.83$), and a multiple-of-32 formula that evaluates
to 448 rather than the claimed 512. These directly affect which chunk the
scheduler selects and therefore the central comparison.
\action{Use the round-based power-of-two form consistently everywhere; verify
every worked numeric example; remove or clearly mark superseded historical
formulas.}

\subsection*{M3 \sev{Major} Generality of the conclusion}
The validated scheduling claim is restricted to Mamba-1.x and to a narrow
medium-high entropy prompt regime in which the optimal chunk is nearly always
the same. A TPDS reader will ask whether ``static wins'' is a property of SSM
scans in general or an artifact of this regime.
\action{Strengthen generality by at least one of: (i) a second linear-recurrence
kernel (e.g., Mamba-2 SSD or a parallel-scan/linear-attention kernel), (ii) a
deliberately heterogeneous workload with wide entropy spread where adaptation
could plausibly help, or (iii) an explicit, quantitative regime boundary that
predicts when online adaptation would and would not pay off. If none is
feasible, retitle/reframe to scope the claim to the measured regime.}

\subsection*{M4 \sev{Major} Positioning against parallel/distributed
scheduling literature}
For TPDS, the related-work framing should foreground parallel-scan scheduling,
kernel autotuning (offline search vs.\ online adaptation), and dynamic dispatch
in accelerator runtimes, and state precisely what is new: an online,
data-dependent scheduling signal evaluated inside the inference critical path,
with a rigorous cost accounting.
\action{Add a focused comparison subsection contrasting COREY's online signal
with offline autotuning and with learned/heuristic dispatch, and articulate
the cost model that makes online adaptation lose here.}

\section{Minor and Technical Issues}

\begin{enumerate}[label=T\arabic*.]
  \item \sev{Minor} Guarded-fallback overhead reduction ($+4.6\%\rightarrow
        +1.3\%$) is reported relative to a separate-run Static-512 baseline.
        State the baseline provenance inline so it is not misread as an
        absolute speedup.
  \item \sev{Minor} Theorem~2 (informal) connective: ``strict inequality
        unless $B$ is a permutation \emph{and} $p$ is uniform'' should be
        ``\emph{or}'' to match the appendix proof.
  \item \sev{Minor} Hadamard entropy-decrease explanation: stating that
        Gaussianity is ``preserved'' does not by itself explain a 1.4-nat
        drop; attribute it explicitly to dynamic histogram binning interacting
        with a non-zero mean (the manuscript already has the right mechanism;
        make the wording self-consistent).
  \item \sev{Minor} Surrogate dispatch-cost recomputation: verify the
        per-call divisor (calls vs.\ 8) in the Tier-1 cost model; an incorrect
        divisor propagates into the surrogate solver latencies.
  \item \sev{Minor} Reproducibility: the abstract references an anonymized
        code/data URL that is currently commented out. Restore an anonymized
        artifact link and add a short reproducibility statement (hardware,
        driver/toolkit versions, seeds, warmup/repeat counts).
  \item \sev{Minor} Cross-device evidence: the multi-GPU/data-center and
        TPU reference points are valuable for TPDS; make sure each is labeled
        with whether it is kernel-isolated or end-to-end, to avoid apples-to-
        oranges readings.
\end{enumerate}

\section{Concrete Revision Roadmap}

\begin{enumerate}[label=\textbf{A\arabic*.}]
  \item \textbf{Rigor pass (M1, M2, T1--T4).} Unify the timing protocol,
        re-audit all latency tables for warmup/JIT parity, and reconcile every
        formula with the implementation and its worked examples.
  \item \textbf{Generality (M3).} Add a second kernel/architecture or a
        wide-spread workload, or state a quantitative regime boundary; scope
        the central claim accordingly.
  \item \textbf{Positioning (M4).} Add a parallel-scan / autotuning /
        dynamic-dispatch comparison and a crisp novelty statement for a
        systems audience.
  \item \textbf{Reproducibility (T5).} Restore the anonymized artifact and add
        a reproducibility statement and environment table.
  \item \textbf{Presentation.} Keep the honest negative framing, but lead with
        the transferable systems lesson: the decision-quality vs.\
        decision-cost decomposition and the conditions under which online
        kernel adaptation is (un)justified.
\end{enumerate}
