\subsection*{Must-Fix 1: Abstract Still Overstates the Data-Center Calibrated Result}

The abstract currently says that the calibrated rule
\[
H_{\mathrm{ref}}=\log K
\]
matches the one-time-profile static oracle and achieves
\[
4.41\times
\]
on a consumer GPU and
\[
3.90\text{--}4.04\times
\]
on a data-center accelerator.

This is potentially confusing because the H800/data-center rows reported
as \(3.90\text{--}4.04\times\) are now described in the paper as a
\emph{legacy-reference} \(H_{\mathrm{ref}}=8.0\) diagnostic, not as the
submitted calibrated default. The calibrated default is cleanly shown for
the consumer GPU and server-class GPU in Table 5, but the H800 Table 4
row is explicitly legacy and does not collect the calibrated chunk-512
COREY point as a COREY row.

\paragraph{Recommended abstract replacement.}

Replace the current abstract sentence:

\begin{quote}
At the kernel level, the calibrated rule (\(H_{\mathrm{ref}}=\log K\))
selects the locally optimal chunk size and matches a one-time-profile
static oracle, achieving \(4.41\times\) lower latency than the unoptimized
baseline on a consumer GPU and \(3.90\text{--}4.04\times\) on a
data-center accelerator.
\end{quote}

with the safer version:

\begin{quote}
At the kernel level, the calibrated rule
(\(H_{\mathrm{ref}}=\log K\)) selects the locally optimal chunk size
and matches a one-time-profile static oracle on the measured
consumer and server-class GPU sweeps, achieving \(4.41\times\)
and \(3.55\times\) lower latency than the Static-64 baseline,
respectively. H800 measurements are reported separately as a
legacy-reference sensitivity diagnostic and as the platform for the
routed end-to-end ablation.
\end{quote}

\paragraph{Even shorter abstract-safe version.}

If space is tight, use:

\begin{quote}
At the kernel level, the calibrated rule
(\(H_{\mathrm{ref}}=\log K\)) selects the locally optimal chunk size
and matches a one-time-profile static oracle on the measured
consumer and server-class GPU sweeps, while H800 routed
end-to-end inference remains performance-negative due to online
scheduling overhead.
\end{quote}

\subsection*{Must-Fix 2: Remove Remaining \texttt{dinner} Typos}

There are still several occurrences of \texttt{dinner} in the main paper
and supplementary material. These are obvious typographical artifacts
and should be fixed before submission.

\paragraph{Required replacement.}

Globally replace:

\begin{verbatim}
dinner
\end{verbatim}

with:

\begin{verbatim}
d_{\mathrm{inner}}
\end{verbatim}

or, in code-style text,

\begin{verbatim}
d_inner
\end{verbatim}

\paragraph{Examples to fix.}

\begin{quote}
\(\texttt{dinner}=1024\)
\end{quote}

should become:

\begin{quote}
\(d_{\mathrm{inner}}=1024\)
\end{quote}

and

\begin{quote}
\(u \in \mathbb{R}^{B\times \texttt{dinner}\times L}\)
\end{quote}

should become:

\begin{quote}
\(u \in \mathbb{R}^{B\times d_{\mathrm{inner}}\times L}\).
\end{quote}

\subsection*{Must-Fix 3: Fix Appendix Figure 2 Caption Bucket Description}

The appendix now correctly says in Table 18 that the 80 LongBench prompts
map to a single bucket under both references: chunk 256 under the legacy
reference and chunk 512 under the calibrated default. However, the Figure 2
caption still says the distribution is entirely within the chunk-256 band.
That is only true for the legacy mapper and can conflict with the submitted
default \(H_{\mathrm{ref}}=\log K\).

\paragraph{Recommended caption replacement.}

Replace the final part of the Figure 2 caption with:

\begin{quote}
The empirical distribution is narrow and maps to a single coarse bucket
under both references: chunk 256 under the legacy \(H_{\mathrm{ref}}=8.0\)
mapper and chunk 512 under the submitted calibrated
\(H_{\mathrm{ref}}=\log K\) mapper. Thus the real-checkpoint workload
does not exercise broad prompt-level chunk switching, regardless of
which reference is used.
\end{quote}

\subsection*{Optional but Recommended: Clarify Table 4 in Section 5.1}

The main text currently discusses the H800 Table 4 result near the
calibrated default discussion. Because Table 4 is now explicitly labeled
as legacy \(H_{\mathrm{ref}}=8.0\), it is safer to make this distinction even
more explicit.

\paragraph{Suggested replacement paragraph for the Table 4 discussion.}

\begin{quote}
The H800 W1 supplement in Table 4 is retained as a legacy-reference
sensitivity diagnostic rather than as a calibrated-default COREY row.
It shows that the older \(H_{\mathrm{ref}}=8.0\) setting under-selects
chunk 256 while the measured Static-512 row is the per-device static
oracle. We therefore use Table 4 to validate the monotone
chunk--latency trend on H800, not to claim a calibrated COREY
oracle match on that device.
\end{quote}

\subsection*{Checklist Status}

The reproducibility checklist is acceptable but still has two visible
risk points:

\begin{enumerate}
    \item Item 4.12 is answered \texttt{no} for statistical significance tests.
    \item Item 4.13 is answered \texttt{partial} for final hyperparameters.
\end{enumerate}

These are not fatal as long as the paper does not claim statistically
significant speedups for small deltas such as \(+0.7\%\), \(+1.3\%\), or
\(-0.14\%\). The current main text already states that the smallest
individual deltas are not claimed to be statistically significant, which
is appropriate.

\paragraph{Optional checklist-safe statement.}

If space permits, add this sentence near Table 7 or in the limitations:

\begin{quote}
We report small latency differences as diagnostic overhead measurements
rather than as statistically significant improvements; the main empirical
conclusion is the consistent negative ordering of adaptive variants
relative to the best static chunk.
\end{quote}
